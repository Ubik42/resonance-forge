# 产品与技术选型

## 一句话

把 UE 场景里的物体做成真正可演奏的“材质乐器”，而不是再做一个资产审计器。

## 首版边界

首版只做“撞击”，不同时承诺滚动、刮擦、流体和完整物理有限元求解。模态频率来自材质预设或手工调音，碰撞冲量、法向速度和 MIDI 表演数据负责激励模态组。

## 数据链路

```text
Chaos 碰撞 / MIDI Note On
        ↓
撞击能量、明亮度、音高、阻尼
        ↓
UE 模态共振合成器（可独立预听）
        ↓
可选烘焙 WAV + WAAPI 自动建树
        ↓
Wwise Event / RTPC / Spatial Audio / SoundBank
```

## 为什么不把 DSP 第一版直接写成 Wwise Source Plug-in

Wwise Source Plug-in 更接近最终生产形态，但会同时引入 Authoring 插件、Sound Engine 插件、平台编译与许可验证。首版先用 UE `USynthComponent` 验证声音、交互和线程模型，再把稳定 DSP 核心抽成无 UE 依赖库，最后接入 Wwise Source Plug-in。这样每阶段都有可听、可录屏的成果。

## Wwise 作者端计划

- `ImpactEnergy`：撞击强度，控制音量、压缩与高频激励。
- `ContactSpeed`：接触速度，后续用于滚动与刮擦层。
- `MaterialHardness`：材质硬度，控制模态密度和频谱倾斜。
- `ObjectSize`：物体尺度，控制整体音高与衰减。
- `SurfaceWetness`：湿润程度，控制阻尼与滤波。

通过 WAAPI 创建 Actor-Mixer 层级、Sound SFX、Events 和 Game Parameters；实时运行时仍通过官方 Wwise Unreal Integration 设置 RTPC。
