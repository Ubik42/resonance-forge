# 产品与技术选型

## 一句话

把 UE 场景里的物体做成真正可演奏的“材质乐器”，而不是再做一个资产审计器。

## 当前边界

当前作品聚焦两类互补声源：材质撞击体与可演奏数字波导弦，不同时承诺滚动、流体和完整有限元求解。模态频率来自材质预设或手工调音；波导弦复用同一延迟线，以指腹平滑位移、拨片噪声脉冲、锤击局部冲击三种初始条件和一套非线性弓擦持续激励扩展演奏性。碰撞冲量、落点、MIDI 音高与力度继续负责实时激励。

物理碰撞标定不再只露出两个难解释的数值。冲量先减去静默门槛，再乘灵敏度并限制到 `0–1`；相对速度走独立平方根映射进入明亮度。工作台的“冲量标定砧尺”把门槛、50% 与 100% 能量所需冲量画成一条连续标尺，并保留最近一次原始碰撞，即使它没有跨过发声门槛。轻件、道具、重构件三枚砝码只是可编辑起点，不是隐藏的材质音色。

A/B 使用配方级快照，不把一条可视化轮廓当作权威状态。参考版保存材质、模型、模态、弦床、Note、输入力度、力度曲线、弓速、弓压和弓向；交换时先恢复对象与 DSP，再把演奏状态写回运行 Actor 并试听。界面的“配方对照尺”只是这份快照的连续工位视图。

## 数据链路

```text
Chaos 碰撞 / MIDI Note On + Note Off / 试音键床
        ↓
原始力度 → 软触 / 线性 / 重手凸轮 → 激励能量、明亮度、音高、落点与起振手势
        ↓
模态撞击体 / 数字波导弦
        ↓
UE 原声炉 ← 监听闸门 → Wwise Event / 3 RTPC
        ↓
离线铸样 WAV + 可回炉声源铭牌
```

Wwise 侧的六项引用独立保存在 `UResonanceWwiseRoutingProfile`。它和 `UResonanceMaterialProfile` 分工：前者回答“发到哪个 Event / RTPC”，后者回答“物体如何共振”。这样换 Wwise 工程或 Work Unit 时不需要复制整份声学参数，也不会让一个 Demo 的固定 Content 路径成为运行时唯一真相。

## 为什么当前不把 DSP 直接写成 Wwise Source Plug-in

Wwise Source Plug-in 更接近最终生产形态，但会同时引入 Authoring 插件、Sound Engine 插件、平台编译与许可验证。当前先用 UE `USynthComponent` 打磨声音、交互和线程快照，并用监听闸门与 Wwise Event / RTPC 做清晰的双路径验证。只有 DSP 与产品交互稳定后，才值得把核心抽成无 UE 依赖库并评估 Source Plug-in；这不是当前作品虚构完成的能力。

## Wwise 作者端

当前 Demo 使用三项稳定 Wwise 映射；推弓/回弓只进入 UE 原生波导摩擦模型，不虚构额外 RTPC：

- `RF_ImpactEnergy`：撞击强度，通过非线性曲线控制 Voice Volume。
- `RF_ImpactBrightness`：碰撞速度或 MIDI CC1，反向控制 Voice Low-pass。
- `RF_ObjectSize`：物体尺度，以中点为原音高，小物体升调、大物体降调。

WAAPI 负责创建 Random Container、Sound SFX、Event、Game Parameter、RTPC 曲线和 SoundBank；运行时仍由官方 Wwise Unreal Integration 设置参数并发布 Event。

工作台的“路由织机”不是另一个管理后台，而是六项运行时引用的可视化：左侧三条材质线进入实际 Event，右侧三个设计参数进入实际 RTPC。完整绑定可以铸成共享路由资产；缺项时保留场景状态并给出缺口，不创建误导性的半成品。

原生波导弦的 MIDI 与弓行轨会在 Note On 后持续补能，Note Off 进入 140 ms 收弓；按钮、键床和双轮微调保留有限自动弓程。弓行轨把横向速度、移动符号和纵向压入分别映射为弓速、推弓/回弓与弓压，换弓方向用 10 ms 平滑穿过零点。持音期间的 CC1 经过 18 ms 平滑后改变弓速并实时更新 Wwise `RF_ImpactBrightness`，Channel / Note Aftertouch 经过 12 ms 平滑后独立改变弓压。Wwise 参考 Event 仍按 Note On 一次性发布，不在没有 Authoring Stop Event 的情况下虚构停止链。
